# 논문값과 재현값이 다른 이유: 확인된 원인

DLinear 논문(Zeng et al., AAAI 2023)의 표를 공식 코드(cure-lab/LTSF-Linear)로 재현했을 때 생긴 차이를 원인별로 정리한다. 여기에는 실험으로 직접 확인한 것만 적는다. 아직 설명하지 못한 차이는 `open_problems.md`에 따로 있다.

- 작성일: 2026-11-13
- 실험 환경: Colab T4(GPU), CPU 전용 환경(PyTorch 2.x), 일부는 PyTorch 1.9.0
- 원자료: 이 폴더의 CSV 파일. 각 절 끝에 파일 이름을 적었다.

## 2. 스크립트의 학습률이 논문 이후에 바뀌었다

| 칸 | 2022-06 스크립트 | 2022-08 스크립트 | 논문값이 나오는 설정 |
|---|---|---|---|
| ETTm2 720 | 0.1 | 0.01 (2022-08-22 `726695f`) | 2022-06 코드 + 학습률 0.01 → 0.3971 / 0.4211 (논문 0.397 / 0.421) |

## 3. 테스트의 마지막 배치를 버리는 방식

2023-03-15 이전 코드는 테스트에서 배치 크기에 못 미치는 마지막 묶음을 버렸다. 지금 코드는 버리지 않는다. 1절 표의 "채점만 바꿈" 열이 이 효과다. 6칸에서 가장 큰 차이가 환율 336의 0.005이고 나머지는 0.002 이하다. 빨간 칸의 주된 원인은 아니다.

이 방식은 저자들도 issue #58에서 인정하고 고쳤다. TFB 벤치마크 논문(PVLDB 2024)은 이 방식이 배치 크기에 따라 결과를 바꿔 불공정한 비교를 만든다고 지적한다.

## 4. Traffic은 더 길게 학습한 값이다

2022-06 코드, 스크립트 설정(학습률 0.05, 배치 16) 그대로 돌린 결과다.

| 설정 | MSE | MAE |
|---|---|---|
| 논문 | 0.410 | 0.282 |
| 시드 2021, 최대 10 epoch (기본값) | 0.4112 | 0.2839 |
| 시드 2022, 최대 10 epoch | 0.4118 | 0.2854 |
| 시드 2023, 최대 10 epoch | 0.4123 | 0.2872 |
| 시드 2021, 최대 30 epoch (16번째에서 조기 종료) | 0.4103 | 0.2822 |

- 기본 설정은 10 epoch에서 강제로 끝나는데, 그 시점에도 검증 오차가 줄고 있었다. 상한을 30으로 늘리면 16번째 epoch에서 조기 종료하고 MSE·MAE 모두 논문과 일치한다.
- 시드를 바꾸면 논문값에서 멀어진다. 시드는 원인이 아니다.
- CPU에서 돌린 값(0.4112 / 0.2839)이 Colab T4 값과 같다. 하드웨어 차이도 아니다.
- 공개 스크립트에는 epoch 수가 적혀 있지 않고, 스크립트 자체는 첫 공개 이후 바뀐 적이 없다.

192·336·720도 같은 방법(2022-06 코드, 스크립트 설정, `--train_epochs 30`, 시드 2021)으로 Colab T4에서 돌렸다(2026-11-13). 세 칸 모두 MSE와 MAE가 소수 셋째 자리까지 논문과 같다.

| T | 최대 10 epoch | 최대 30 epoch (조기 종료 시점) | 논문 |
|---|---|---|---|
| 192 | 0.4245 / 0.2912 | 0.4226 / 0.2874 (21 epoch) | 0.423 / 0.287 |
| 336 | 0.4375 / 0.2989 | 0.4357 / 0.2955 (16 epoch) | 0.436 / 0.296 |
| 720 | 0.4680 / 0.3180 | 0.4656 / 0.3145 (19 epoch) | 0.466 / 0.315 |

Colab 노트북은 테스트 오차를 배치마다 누적해서 계산하도록 고친 판이다(메모리 부족 때문). 같은 계산으로 ETTh1 96과 Traffic 96에서 원래 코드와 같은 값이 나오는 것을 확인했다.

원자료: `traffic96_june2022_code.csv`, `traffic96_epoch_curve.csv`, `traffic_ep30_colab.csv`, 노트북 `DLinear_traffic_ep30.ipynb`

## 6. 논문 Table 9의 단변량 ETTh1 720은 오타다

## 7. 공식 LTSF-Benchmark.md의 행 이름이 바뀌어 있다

저장소의 `LTSF-Benchmark.md` 둘째 표(전력, 환율, 교통, 날씨, 독감)에서 "DLinear"라고 적힌 행에 논문의 NLinear 값이, "NLinear"라고 적힌 행에 논문의 DLinear 값이 들어 있다. 예를 들어 독감 24의 2.215와 환율 96의 0.081은 논문에서 DLinear 값인데, 이 표에서는 NLinear 행에 있다. 첫째 표(ETT 4종)는 정상이다. 이 표로 재현값을 대조할 때는 두 행을 바꿔서 봐야 한다.

## 9. 조기 종료가 앞쪽 epoch를 고른 칸은 난수에 흔들린다

2022-06 코드에서 최대 30 epoch, 조기 종료 없이 매 epoch의 테스트 MSE를 기록했다. 학습률은 매 epoch 절반으로 줄어서(type1) 30 epoch면 사실상 수렴한다.

| 칸 | 1 epoch | 5 epoch | 30 epoch | 학습 없이 푼 해 | 논문 |
|---|---|---|---|---|---|
| ETTh1 192 | 0.412 | 0.405 | 0.405 | 0.404 | 0.405 |
| ETTh2 720 | 1.391 | 0.605 | 0.738 | 0.741 | 0.605 |
| 환율 720 | 0.643 | 1.489 | 1.099 | 1.100 | 0.643 |

- ETTh1 192는 학습할수록 좋아지고, 수렴한 값이 곧 논문값이다.
- ETTh2 720은 5번째 epoch에 논문값을 지난 뒤 나빠져서 학습 없이 푼 해로 수렴한다. 환율 720은 첫 epoch가 논문값이다.
- 기본 설정에서는 검증 오차가 가장 낮은 epoch의 모델로 채점하고, 3 epoch 동안 나아지지 않으면 멈춘다. 이 칸들에서는 그 epoch가 학습 초반에 걸렸다. 초반의 값은 초기화와 데이터 순서에 크게 좌우되므로, 쓰지 않는 층 하나(1절)나 시드 하나(덧붙임)로 결과가 크게 달라진다.
- 초기화를 빼거나 쓰지 않는 층까지 빼도 30 epoch 뒤의 값은 같은 곳으로 간다(ETTh2 720: 0.738~0.740, 환율 720: 1.099~1.102). 코드 변경은 "어디로 수렴하느냐"가 아니라 "몇 번째 epoch에서 멈추느냐"를 바꾼다.

## 10. 순서 섞기 실험(Table 5)은 입력 길이 96이다

논문 Table 5는 Linear를 원래 순서로 학습한 뒤 입력 순서를 바꿔 넣었을 때 오차가 얼마나 늘어나는지 보여준다. 논문 본문에는 입력 길이와 "테스트 때만 바꾸는지"가 적혀 있지 않다. 환율 데이터에서 테스트 때만 바꾸고, 입력 길이를 네 가지로 돌렸다(시드 5개 평균, MSE).

| 입력 길이 | 원래 (96 / 192 / 336 / 720) | 전체 섞기 평균 악화 | 앞뒤 절반 바꾸기 평균 악화 |
|---|---|---|---|
| 96 | 0.085 / 0.161 / 0.304 / 0.786 | +27.8% | +45.0% |
| 192 | 0.082 / 0.161 / 0.302 / 0.846 | +65.9% | +75.3% |
| 336 | 0.090 / 0.166 / 0.339 / 0.935 | +113.4% | +156.6% |
| 720 | 0.092 / 0.188 / 0.373 / 1.175 | +237.0% | +286.6% |
| 논문 Table 5 | 0.080 / 0.162 / 0.286 / 0.806 | +27.26% | +46.81% |

- 입력 길이 96에서 두 악화율이 논문과 거의 같다(+27.8% 대 +27.26%, +45.0% 대 +46.81%). 원래 값도 Table 2(입력 길이 336)보다 Table 5 쪽에 가깝다.
- 입력이 길수록 섞였을 때 잃는 정보가 많아 악화 폭이 커진다. 즉 Table 5의 27%, 47%는 입력 길이 96에서의 값이고, 논문의 주 설정인 336에서는 Linear가 순서에 훨씬 더 크게 의존한다(+113%, +157%).
- 학습 때도 똑같이 바꾸면 앞뒤 절반 바꾸기의 악화는 0%가 된다(입력 길이 336: −0.1%~+0.1%). 고정된 순서 바꾸기는 선형 모델이 그대로 배울 수 있기 때문이다. 따라서 논문은 테스트 때만 바꿨다고 보는 것이 맞다.
- 평균 악화는 예측 길이별 악화율의 평균이다. 논문 Table 5의 숫자로 역산해 같은 계산임을 확인했다.
- Transformer 쪽(FEDformer, Autoformer, Informer)은 돌리지 않았다.

## 11. 단변량 표에서 스크립트와 다른 학습률로 돌린 줄 (2026-11-21 고쳐 씀)

### 먼저, 이전 판의 잘못

이전 판은 단변량 16칸 중 13칸이 "당시 스크립트 그대로 일치"한다고 적었다. MSE와 MAE를 모두 소수 셋째 자리까지 보는 엄격한 기준으로 다시 세면 11칸이다. 두 칸을 일치로 잘못 셌다.

| 칸 | 2022-06 코드, 스크립트 설정 | 논문 | 어긋난 곳 |
|---|---|---|---|
| ETTh2 192 | 0.1749 / 0.3285 | 0.176 / 0.329 | MSE와 MAE 모두 0.001 |
| ETTm2 336 | 0.1186 / 0.2605 | 0.119 / 0.261 | MAE 0.001 (반올림 경계) |

### 방법: 이웃 칸으로 가르기

논문 표는 소수 셋째 자리까지만 있어서, 한 칸만 보면 논문값이 나오는 설정이 여러 개 나올 수 있다. 실제로 ETTh2 96은 두 개, ETTh2 192는 세 개였다. 그래서 "같은 스크립트 파일의 이웃 줄도 같은 설정으로 돌렸을 것"이라는 가정을 추가했다. 후보 설정이 이웃 칸에서도 논문값을 내면 받아들이고, 이웃 칸을 깨뜨리면 버린다.

### 단변량 ETTh2 96·192: 학습률 0.05

2022-06 코드, 배치 32.

| 설정 | 96 | 192 | 336 | 720 |
|---|---|---|---|---|
| 스크립트 (학습률 0.005) | 0.1329 / 0.2808 ✗ | 0.1749 / 0.3285 ✗ | 0.2088 / 0.3674 ✓ | 0.2757 / 0.4257 ✓ |
| 학습률 0.05 | 0.1308 / 0.2792 ✓ | 0.1763 / 0.3290 ✓ | 0.2055 / 0.3650 ✗ | 0.2905 / 0.4383 ✗ |
| 학습률 0.005, 배치 16 | 0.1311 / 0.2794 ✓ | 0.1767 / 0.3292 ✗ | | |
| 논문 | 0.131 / 0.279 | 0.176 / 0.329 | 0.209 / 0.367 | 0.276 / 0.426 |

- 학습률 0.05는 96과 192를 함께 맞춘다. 이전 판의 다른 후보(학습률 0.005, 배치 16)는 192에서 어긋난다. 그래서 96·192는 학습률 0.05로 확정한다.
- 336과 720은 스크립트의 0.005에서 맞고 0.05에서는 어긋난다. 한 파일 안에서 앞의 두 줄과 뒤의 두 줄의 학습률이 달랐던 셈이다. 같은 묶음의 단변량 ETTm2 스크립트가 바로 그런 모양이다(96·192는 0.001, 336·720은 0.01). 다변량 ETTh2 스크립트의 학습률도 0.05다.
- 2022-08 코드에서는 스크립트 설정 그대로 96이 0.1310 / 0.2791로 맞는다. 하지만 같은 코드에서 192는 0.1752 / 0.3283으로 어긋나므로, "8월 코드로 다시 돌렸다"는 설명은 두 칸을 함께 설명하지 못한다.
