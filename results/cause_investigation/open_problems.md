# 원인을 찾지 못한 차이: 문제 정의

재현한 92칸(다변량 DLinear 36, 단변량 DLinear 16, NLinear 20, Linear 20) 중 원인을 끝내 찾지 못한 세 칸을, 다음 사람이 이어서 볼 수 있게 문제로 정의한다. 원인을 확인한 칸은 `confirmed_causes.md`에 있다.

- 작성일: 2026-11-13, 고쳐 씀 2026-11-21
- 원자료: 이 폴더의 CSV 파일. 각 절에 파일 이름을 적었다.
- 2026-11-21에 바뀐 것: (1) 단변량 ETTh2 96은 학습률 0.05로 확정해 `confirmed_causes.md` 11절로 옮겼다. (2) NLinear ETTm2 336은 "설정 후보 두 개"에서 "원인 모름"으로 옮겼다(문제 3). (3) 두 칸에 가설 세 개를 더 시험했다.

## 한눈에 보기

| 구분 | 칸 수 | 어디에 |

| 원인 확인, 논문값 재현 | 89 | `confirmed_causes.md` |
| 원인 모름 | 3 | 이 문서 |

기준은 MSE와 MAE가 모두 소수 셋째 자리까지 같은 것이다. Linear의 두 칸(ETTh1 336, ETTh2 720)은 MSE가 같고 MAE만 반올림 경계에서 0.001 다르다. 이 두 칸은 원인 확인 쪽에 넣었다.

| 번호 | 칸 | 재현 (MSE / MAE) | 논문 | 차이 | 판단 |
|---|---|---|---|---|---|

## 문제 1. 다변량 DLinear ETTm2 96

### 관측

2022-06 코드(`04ffd8d`)와 당시 스크립트(입력 336, 학습률 0.001, 배치 32, 시드 2021)로 돌리면 0.16766 / 0.25980이 나온다. 반올림하면 0.168 / 0.260이고, 논문 Table 2는 0.167 / 0.260이다. MAE는 맞고 MSE만 반올림 경계 너머 0.0007 높다. 같은 코드와 같은 시드로 다른 35칸은 모두 논문과 일치한다.

### 문제

> 어떤 코드·설정에서 MSE 0.167과 MAE 0.260이 **함께** 나오는가?

판정 기준: 두 지표 모두 소수 셋째 자리까지 일치하고, 그 설정이 같은 스크립트의 다른 칸(ETTm2 192·336·720)과도 모순되지 않을 것.

### 배제한 가설

| 가설 | 확인 방법 | 결과 |
|---|---|---|
| 학습률이 다르다 | 0.05 / 0.01 / 0.005 / 0.001 / 0.0005 / 0.0001 | 두 지표를 동시에 맞추는 값 없음 (`lr_batch_sweeps.csv`) |
| 배치가 다르다 | 8 / 16 / 32 / 64 (학습률 0.001) | 없음. 8: 0.1676 / 0.2602, 16: 0.1685 / 0.2597, 64: 0.1663 / 0.2565 (`last_open_cells_sweeps.csv`) |
| 더 오래 학습했다 (Traffic처럼) | 학습 로그 | 7번째 epoch에 조기 종료한다. 상한 10에 닿지 않으므로 상한을 늘려도 결과가 같다 |
| 테스트 마지막 배치 채점 | 마지막 배치까지 채점 | 0.16765 / 0.25980, 그대로 |
| 표를 버림으로 적었다 | 버림 계산 | MSE는 0.167이 되지만 MAE가 0.259가 되어 논문 0.260과 어긋난다 |
| 데이터 파일 버전 | 공식 ETDataset 저장소와 md5 비교, 파일 이력 확인 | 같은 파일. ETTm2.csv의 마지막 수정은 2021-03-11로 논문보다 앞선다 |
| 실행 환경 | 다른 칸에서 GPU와 CPU, PyTorch 1.9.0과 2.x 비교 | 소수 넷째 자리까지 같다 |
| 코드 버전 | 첫 공개(2022-05-27)부터 `04ffd8d`까지 비교 | 모델·학습 코드는 사실상 같다 |
| 조기 종료·학습률 일정 | patience, lradj 변경 | 아래 "추가 확인" 참고 |
| 개별 버전(`--individual`) | 2022-06 코드에서 옵션 추가 | 0.1949 / 0.2880, 더 멀어진다 |

### 이 칸은 시드에 얼마나 흔들리는가 (2026-11-16)

같은 코드와 설정에서 시드만 바꿨다(`hypothesis_tests_last_cells.csv`).

| 시드 | MSE | MAE | 반올림 |
|---|---|---|---|
| 2021 (논문 시드) | 0.1677 | 0.2598 | 0.168 / 0.260 |
| 2022 | 0.1666 | 0.2602 | **0.167 / 0.260 (논문과 일치)** |
| 2023 | 0.1664 | 0.2596 | 0.166 / 0.260 |
| 2024 | 0.1708 | 0.2677 | 0.171 / 0.268 |
| 2025 | 0.1663 | 0.2594 | 0.166 / 0.259 |
| 2026 | 0.1678 | 0.2607 | 0.168 / 0.261 |

- 시드만 바꿔도 MSE가 0.166 ~ 0.171로, 논문과의 차이(0.0007)보다 여섯 배 넘게 흔들린다. 이 칸은 4번째 epoch에서 가장 좋은 검증 오차가 나오고 7번째에 조기 종료하는, 학습 초반에 멈추는 칸이다(`confirmed_causes.md` 9절과 같은 종류).
- 시드 2022는 논문과 두 지표 모두 일치한다. 다만 다른 35칸은 시드 2021로 맞으므로, 저자가 이 칸만 다른 시드로 돌렸다고 볼 근거는 없다.
- 해석: 이 칸의 0.0007은 실행마다 생기는 흔들림 안쪽에 있다. 저자 환경과 이 환경 사이의 아주 작은 차이로도 충분히 생길 수 있는 크기다. 무엇이 그 차이였는지는 여전히 모른다.

### 남은 가설 (모두 미확인)

1. **저자 GPU의 비결정적 연산.** cuDNN 같은 비결정적 연산이 마지막 자리를 바꿨을 수 있다. 다만 T4와 CPU 결과가 넷째 자리까지 같았으므로 근거는 약하다. 확인하려면 다른 GPU(V100, A100 등)에서 같은 실행을 여러 번 돌려 결과가 흔들리는지 본다.
2. **시드 2021이 아닌 실행.** 다른 35칸이 모두 시드 2021과 맞으므로 가능성은 낮다. 시드를 여러 개 돌려 0.167 / 0.260이 나오는 시드가 있는지 볼 수는 있지만, 찾더라도 저자가 그 시드를 썼다는 증거는 되지 않는다.

### 영향

0.0007은 표의 마지막 자리 하나다. 발표의 어떤 결론(코드 버전이 원인, 학습 초반에 멈춘 칸은 시드에 흔들림 등)도 바뀌지 않는다. "반올림 수준, 원인 모름"으로 닫는다.

## 문제 2. NLinear 환율 720

### 관측

2022-08 코드(`7f7a25b`, NLinear가 처음 공개된 시점)와 당시 스크립트(입력 336, 학습률 0.0005, 배치 32, 시드 2021)로 0.9430 / 0.7283이 나온다. 논문 Table 2는 1.033 / 0.780이다. 재현값이 오히려 더 좋다. NLinear의 다른 19칸은 같은 코드에서 논문값이 나오는 설정을 찾았다.

### 문제

> 어떤 코드·설정에서 MSE 1.033과 MAE 0.780이 **함께** 나오는가?

판정 기준: 두 지표 모두 소수 셋째 자리까지 일치하고, 그 설정 또는 코드 변경을 NLinear의 다른 19칸에 적용해도 그 칸들이 계속 논문과 맞을 것.

### 배제한 가설

| 가설 | 확인 방법 | 결과 |
|---|---|---|
| 학습률이 다르다 | 0.05 ~ 0.0001, 6개 (배치 32) | 0.8831 ~ 1.0412. MSE가 1.03 근처면 MAE는 0.758 ~ 0.763 (`nlinear_linear_lr_sweep_aug2022.csv`) |
| 배치가 다르다 | 8, 16 × 학습률 3개 | 0.9536 ~ 1.1234. 맞는 조합 없음 (`last_open_cells_sweeps.csv`) |
| 시드 | 2021 ~ 2025 | 0.943 ~ 0.958. DLinear와 달리 이 칸의 NLinear는 시드에 안정적이다 |
| 입력 길이 | 96 / 192 / 336 / 512 / 720 | 0.8997 ~ 1.0150 |
| 개별 버전(`--individual`) | 2022-08 코드에서 옵션 추가 | 결과가 똑같다. 이 시점의 NLinear는 옵션을 받지 않는다 |
| 1/L 가중치 초기화 | 코드에 주석으로 남은 초기화 줄을 켜고 시드 5개 | 0.9415 ~ 0.9563, 끈 경우와 거의 같다 (`nlinear_exchange720_init_check.csv`) |
| 이후 코드 버전 | 저장소 이력 확인 | NLinear 파일은 2022-12(`b9ca453`, 개별 버전 추가)에만 바뀌었고 기본 경로는 같다. 환율 스크립트는 2022-08 이후 그대로다. 2023-03 채점 변경의 영향은 다른 칸에서 0.005 이하였다 |
| 표 옮기다 생긴 오타 | 저자의 LTSF-Benchmark.md와 대조 | 같은 1.033 / 0.780이 Benchmark.md에도 있다(행 이름은 DLinear로 바뀌어 있음, `confirmed_causes.md` 7절). 두 곳이 같으므로 오타로 보기 어렵다 |
| 개별 버전의 값이 들어갔다 | Benchmark.md의 개별 버전 값 대조 | NLinear-I 1.133 / 0.785, DLinear-I 1.499 / 0.940, Linear-I 1.658 / 1.033. 어느 것도 같지 않다 |
| 조기 종료·학습률 일정 | patience, epoch 상한, lradj 변경 | 아래 "추가 확인" 참고 |
| 개별 버전으로 돌린 값 | 2022-12 코드(`b9ca453`)에서 `--individual`, 시드 3개, 학습률 3개 | 시드별 0.9766 ~ 1.0067 / 0.7278 ~ 0.7363. MSE는 가까워지지만 MAE가 0.78에 닿지 않는다. 학습률 0.005: 1.0746 / 0.7590, 0.05: 1.5681 / 0.9131 |
| 이후 코드로 직접 실행 | 2022-12 코드, 현재 코드(`0c11366`) | 2022-12: 0.9430 / 0.7283 (8월과 같음). 현재: 0.9254 / 0.7216, 개별 버전 0.9850 / 0.7269 |
| 내부 버전이 다른 정규화였다 | 마지막 값 대신 입력 구간 평균을 빼는 변형, 학습률 2개 | 0.9736 / 0.7416, 1.0075 / 0.7545. 맞지 않는다 |
| 단변량 실행 값이 들어갔다 | `--features S`, `MS` (대상 열 OT) | 둘 다 0.8032 / 0.7196. 맞지 않는다 |

### 관찰된 제약

모든 실행(위의 개별 버전, 평균 빼기 변형, 이후 코드 포함)에서 MSE가 1.0 ~ 1.08일 때 MAE는 0.73 ~ 0.76이다. 논문의 MAE 0.780은 이 관계에서 벗어난다. 학습률, 배치, 입력 길이처럼 공개 스크립트에 있는 값만 바꾸어서는 이 쌍이 나오지 않는다는 뜻이다. 오차의 모양 자체(큰 오차가 어디서 나는지)가 다른 실행이었을 가능성이 있다.

### 남은 가설 (모두 미확인)

1. **공개 전 내부 버전의 NLinear.** NLinear는 논문 최종본과 같은 시기(2022-08)에 처음 공개됐다. 표를 만든 실행은 그 전의 내부 코드였을 수 있다. 정규화 방식을 바꾼 변형(예: 마지막 값 대신 평균을 빼기)을 시험해 볼 수는 있다. 하지만 변형을 많이 시도할수록 우연히 맞을 위험이 커지므로, 판정 기준대로 다른 19칸도 함께 맞을 때만 받아들인다.
2. **공개되지 않은 실행 설정의 조합.** 학습률, 배치, 입력 길이를 동시에 바꾼 조합은 다 훑지 않았다. 다만 관찰된 제약으로 보면 이 방향으로 MAE 0.780에 닿기는 어렵다.

### 다음 단계

## 문제 3. NLinear ETTm2 336 (2026-11-21 추가)

### 관측

2022-08 코드(`7f7a25b`)와 당시 스크립트(입력 336, 학습률 0.01, 배치 32)로 0.2748 / 0.3271이 나온다. 논문은 0.274 / 0.327이다. MAE는 맞고 MSE만 반올림 경계 너머 0.0008 높다.

### 이전 판의 설명과 그것을 버린 이유

배치를 8로 줄이면 학습률 0.01(0.2741 / 0.3269)과 0.005(0.2745 / 0.3270)에서 논문값이 나온다. 이전 판은 이것을 "설정 후보 두 개"로 적었다. 이웃 칸으로 검증하니 배치 8은 탈락했다(`neighbor_cell_tests.csv`).

| 배치 | 96 | 192 | 336 | 720 |
|---|---|---|---|---|
| 32 (스크립트) | 0.1671 / 0.2554 ✓ | 0.2214 / 0.2932 ✓ | 0.2748 / 0.3271 ✗ | 0.3682 / 0.3843 ✓ |
| 8 | 0.1651 / 0.2546 ✗ | 0.2197 / 0.2916 ✗ | 0.2741 / 0.3269 ✓ | 0.3707 / 0.3863 ✗ |
| 논문 | 0.167 / 0.255 | 0.221 / 0.293 | 0.274 / 0.327 | 0.368 / 0.384 |

- 배치 8은 같은 스크립트의 나머지 세 칸을 모두 깨뜨린다. 저자가 스크립트를 배치 8로 돌렸다면 세 칸이 맞을 수 없다.
- 같은 스크립트를 쓰는 Linear의 ETTm2 336도 배치 32에서 맞고(0.3196 / 0.3727, 논문 0.320 / 0.373) 배치 8에서는 크게 어긋난다(0.2847 / 0.3459).
- 남는 가능성은 "336 한 줄만, NLinear만 배치 8로 돌렸다"인데, 그렇게 볼 근거가 없다. 이 칸의 결과는 설정에 따라 0.274~0.281에 몰려 있어서, 21가지 중 두 가지가 맞은 것은 우연으로 보는 편이 자연스럽다.

### 문제

> 어떤 코드·설정에서 MSE 0.274와 MAE 0.327이 함께 나오고, 같은 설정이 ETTm2의 나머지 세 칸도 깨뜨리지 않는가?

## 2026-11-21에 더 시험한 가설 (세 칸 공통)

| 가설 | 확인 방법 | 결과 |
|---|---|---|
| 같은 실행의 두세 번째 반복 값이 표에 들어갔다 (`--itr`의 기본값은 2) | `--itr 3`으로 실행 | ETTm2 96: 0.1677, 0.1659, 0.1699. 환율 720: 0.943, 0.922, 0.960. 어느 반복도, 평균도 논문과 맞지 않는다 (`later_iterations_itr3.csv`) |
| 스크립트 전체를 다른 배치로 돌렸다 | NLinear ETTm2 네 칸을 배치 8로 | 이웃 세 칸이 어긋난다 (위 표) |
| 테스트 구간의 범위가 달랐다 (끝이나 앞의 일부 샘플이 빠짐) | 샘플별 오차를 저장해, 앞·뒤에서 32개 단위로 0~3,000개를 뺀 평균을 계산 | ETTm2 96은 두 지표를 맞추는 범위가 없다. NLinear ETTm2 336은 뒤 480개를 뺄 때 한 곳에서만 맞는다. 두 칸에 공통인 범위가 없으므로 원인이 아니다 |

**혼합 정밀도(AMP)도 원인이 아니다 (2026-11-21, Colab T4).** `--use_amp`로 돌리면 ETTm2 96은 0.167664 / 0.259835, 환율 720은 0.943012 / 0.728276으로, 기본 실행과 여섯째 자리에서만 다르다(`../paper_experiments/amp.csv`). NLinear ETTm2 336은 돌리지 않았다.
