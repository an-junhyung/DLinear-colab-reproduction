## 1. Traffic 192·336·720

### 현상

2022-06 코드와 스크립트(학습률 0.05, 배치 16, 최대 10 epoch)로 돌린 값이 논문보다 조금 높다.

| T | 재현 MSE / MAE | 논문 MSE / MAE |
|---|---|---|
| 96 | 0.4112 / 0.2839 | 0.410 / 0.282 |
| 192 | 0.4245 / 0.2912 | 0.423 / 0.287 |
| 336 | 0.4375 / 0.2989 | 0.436 / 0.296 |
| 720 | 0.4680 / 0.3180 | 0.466 / 0.315 |

### 지금까지 확인한 것

- 96은 최대 epoch를 30으로 늘리면 0.4103 / 0.2822로 논문과 일치한다.
- 시드(2021, 2022, 2023), GPU와 CPU, 데이터 파일은 원인이 아니다.
- Traffic 스크립트는 첫 공개 이후 바뀐 적이 없다.

### 가설

192·336·720도 96과 같이 10 epoch보다 길게 학습한 값이다.

### 확인 방법

2022-06 코드에서 `--train_epochs 30`을 붙여 세 칸을 돌린다. 예측 길이가 길면 한 실행이 메모리를 5GB 넘게 써서 CPU 전용 환경(8GB)에서는 죽었다. Colab T4에서 돌려야 한다.

### 판정 기준

세 칸 모두 MSE와 MAE가 소수 셋째 자리까지 논문과 같으면 해결. 하나라도 다르면 Traffic은 "96만 확인"으로 남긴다.

## 2. 단변량 ETTh2 96의 정확한 설정

### 현상

스크립트 설정(학습률 0.005, 배치 32)으로는 0.1329 / 0.2808이 나온다. 논문은 0.131 / 0.279다.

### 지금까지 확인한 것

학습률 6개와 배치 3개를 조합한 18가지를 돌렸다. 논문과 두 지표 모두 일치하는 조합이 둘이다.

| 학습률 | 배치 | MSE | MAE |
|---|---|---|---|
| 0.05 | 32 | 0.1308 | 0.2792 |
| 0.005 | 16 | 0.1311 | 0.2794 |

PyTorch 1.9.0에서도 스크립트 설정의 결과는 같다(0.1329).

### 왜 더 못 가는가

논문은 소수 셋째 자리까지만 적는다. 두 후보가 그 자리까지 같아서 실험으로는 가릴 수 없다. 같은 스크립트의 192·336·720은 스크립트 설정 그대로 논문과 일치하므로, 다른 칸에서 힌트를 얻을 수도 없다.

### 남은 방법

저자에게 GitHub issue로 묻는다. 물을 내용: "단변량 ETTh2 96(Table 9)을 만들 때 쓴 학습률과 배치 크기."

## 3. 다변량 ETTm2 96

### 현상

2022-06 코드와 스크립트(학습률 0.001, 배치 32)로 0.1677 / 0.2598이 나온다. 반올림하면 0.168 / 0.260이고, 논문은 0.167 / 0.260이다. MSE만 0.0007 다르다.

### 지금까지 확인한 것

| 학습률 | MSE | MAE |
|---|---|---|
| 0.05 | 0.1933 | 0.2917 |
| 0.01 | 0.1681 | 0.2605 |
| 0.005 | 0.1688 | 0.2644 |
| 0.001 (스크립트) | 0.1677 | 0.2598 |
| 0.0005 | 0.1676 | 0.2566 |
| 0.0001 | 0.1645 | 0.2573 |

MSE 0.167과 MAE 0.260을 동시에 주는 학습률은 없다.

### 가능한 설명 (모두 미확인)

- 논문이 반올림이 아니라 버림으로 적었다. 0.1677을 버리면 0.167이다. 다만 다른 칸들은 반올림과 맞아서, 이 칸만 버림일 이유가 없다.
- 배치 크기가 달랐다. 배치는 아직 바꿔 보지 않았다.

### 확인 방법

배치 8, 16, 64로 돌려 본다. 그래도 안 맞으면 "반올림 수준의 차이, 원인 모름"으로 닫는다.

## 4. NLinear·Linear의 불일치 칸

### 현상

2022-08 코드와 스크립트로 돌린 결과 중 논문과 다른 칸이다(MSE).

| 모델 | 칸 | 재현 | 논문 | 차이 |
|---|---|---|---|---|
| NLinear | ETTh2 96 | 0.2833 | 0.277 | +0.006 |
| NLinear | ETTh2 192 | 0.3554 | 0.344 | +0.011 |
| NLinear | ETTm2 720 | 0.3763 | 0.368 | +0.008 |
| NLinear | 환율 720 | 0.9430 | 1.033 | −0.090 |
| Linear | ETTh2 96 | 0.2820 | 0.288 | −0.006 |
| Linear | ETTh2 192 | 0.3891 | 0.377 | +0.012 |
| Linear | ETTh2 336 | 0.4219 | 0.452 | −0.030 |
| Linear | ETTm2 720 | 0.3909 | 0.413 | −0.022 |

나머지 NLinear 16칸과 Linear 16칸은 0.002 이내로 맞는다.

### 가설

DLinear에서와 같은 종류의 문제다. 스크립트 폴더 하나(`scripts/EXP-LongForecasting/Linear/`)를 세 모델이 같이 쓰는데, 논문 표를 만들 때는 모델마다 다른 학습률을 썼을 수 있다. 불일치가 ETTh2, ETTm2, 환율에 몰려 있다는 점이 DLinear 때와 같다.

### 확인 방법

불일치 8칸에 대해 학습률과 배치를 훑는다. DLinear 단변량 때 쓴 것과 같은 방식이다. 2022-08-15 이후 스크립트 변경 이력(`726695f` 등)도 함께 본다.

## 5. "논문값은 중간에 멈춘 결과"라는 해석

### 현상

학습 없이 최소제곱으로 구한 해는 ETTh2 720에서 0.741, 환율 720에서 1.100이다. 논문값(0.605, 0.643)보다 훨씬 나쁘다. 같은 칸들이 시드와 코드 변경에 가장 민감하다.

### 해석

수준이 변하는 데이터에서는 학습 데이터에 완전히 맞춘 해가 테스트에서 나쁘다. 논문의 좋은 값은 학습이 덜 된 지점에서 멈춘 결과이고, 그 지점은 초기화·학습률·난수 순서에 따라 달라진다.

### 아직 없는 증거

- epoch별 테스트 오차 곡선. 학습이 진행될수록 테스트 오차가 다시 올라가는지 직접 본 적이 없다.
- 규제를 넣은 최소제곱(Ridge)으로 논문값 근처가 나오는지.
- 가중치 1/L 초기화가 "평균 근처에서 출발"하게 한다는 설명의 직접 확인.

### 확인 방법

1. ETTh2 720과 환율 720에서 2022-06 코드로 epoch마다 테스트 오차를 기록한다(조기 종료 없이 30 epoch).
2. Ridge 계수를 바꿔 가며 최소제곱 해의 테스트 오차를 본다.
3. 초기화를 0, 1/L, 기본값으로 바꿔 학습 곡선을 비교한다.
