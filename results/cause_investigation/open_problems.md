## 1. Traffic 192·336·720 (해결)

> 2026-11-13 Colab T4에서 `--train_epochs 30`으로 돌린 결과 세 칸 모두 MSE·MAE가 논문과 일치했다(192: 0.4226 / 0.2874, 336: 0.4357 / 0.2955, 720: 0.4656 / 0.3145). 가설이 맞았고 `confirmed_causes.md` 4절로 옮겼다. 아래는 확인 전 기록이다.

### 현상

2022-06 코드와 스크립트(학습률 0.05, 배치 16, 최대 10 epoch)로 돌린 값이 논문보다 조금 높다.

| T | 재현 MSE / MAE | 논문 MSE / MAE |
|---|---|---|
| 96 | 0.4112 / 0.2839 | 0.410 / 0.282 |
| 192 | 0.4245 / 0.2912 | 0.423 / 0.287 |
| 336 | 0.4375 / 0.2989 | 0.436 / 0.296 |
| 720 | 0.4680 / 0.3180 | 0.466 / 0.315 |

### 지금까지 확인한 것

- 96은 최대 epoch를 30으로 늘리면 0.4103 / 0.2822로 논문과 일치한다.
- 시드(2021, 2022, 2023), GPU와 CPU, 데이터 파일은 원인이 아니다.
- Traffic 스크립트는 첫 공개 이후 바뀐 적이 없다.

### 가설

192·336·720도 96과 같이 10 epoch보다 길게 학습한 값이다.

### 확인 방법

2022-06 코드에서 `--train_epochs 30`을 붙여 세 칸을 돌린다. 예측 길이가 길면 한 실행이 메모리를 5GB 넘게 써서 CPU 전용 환경(8GB)에서는 죽었다. Colab T4에서 돌려야 한다.

### 판정 기준

세 칸 모두 MSE와 MAE가 소수 셋째 자리까지 논문과 같으면 해결. 하나라도 다르면 Traffic은 "96만 확인"으로 남긴다.

## 2. 단변량 ETTh2 96의 정확한 설정

### 현상

스크립트 설정(학습률 0.005, 배치 32)으로는 0.1329 / 0.2808이 나온다. 논문은 0.131 / 0.279다.

### 지금까지 확인한 것

학습률 6개와 배치 3개를 조합한 18가지를 돌렸다. 논문과 두 지표 모두 일치하는 조합이 둘이다.

| 학습률 | 배치 | MSE | MAE |
|---|---|---|---|
| 0.05 | 32 | 0.1308 | 0.2792 |
| 0.005 | 16 | 0.1311 | 0.2794 |

PyTorch 1.9.0에서도 스크립트 설정의 결과는 같다(0.1329).

### 왜 더 못 가는가

논문은 소수 셋째 자리까지만 적는다. 두 후보가 그 자리까지 같아서 실험으로는 가릴 수 없다. 같은 스크립트의 192·336·720은 스크립트 설정 그대로 논문과 일치하므로, 다른 칸에서 힌트를 얻을 수도 없다.

### 남은 방법

저자에게 GitHub issue로 묻는다. 물을 내용: "단변량 ETTh2 96(Table 9)을 만들 때 쓴 학습률과 배치 크기."

## 4. NLinear 환율 720

### 현상

2022-08 코드와 스크립트(학습률 0.0005, 배치 32)로 0.9430 / 0.7283이 나온다. 논문은 1.033 / 0.780이다. 재현값이 오히려 더 좋다.

### 지금까지 확인한 것

학습률 6개(배치 32)를 돌렸다. MSE와 MAE를 동시에 맞추는 값이 없다.

| 학습률 | MSE | MAE |
|---|---|---|
| 0.05 | 1.0412 | 0.7634 |
| 0.01 | 1.0140 | 0.7583 |
| 0.005 | 0.9935 | 0.7544 |
| 0.001 | 0.9707 | 0.7399 |
| 0.0005 (스크립트) | 0.9430 | 0.7283 |
| 0.0001 | 0.8831 | 0.7029 |

배치와 시드, 입력 길이도 바꿨다.

| 바꾼 것 | 설정 | MSE | MAE |
|---|---|---|---|
| 배치 8 | 학습률 0.05 / 0.005 / 0.0005 | 1.1234 / 1.0405 / 0.9812 | 0.7965 / 0.7677 / 0.7439 |
| 배치 16 | 학습률 0.05 / 0.005 / 0.0005 | 1.0708 / 0.9982 / 0.9536 | 0.7850 / 0.7543 / 0.7333 |
| 시드 | 2021~2025 (스크립트 설정) | 0.943 ~ 0.958 | 0.728 ~ 0.734 |
| 입력 길이 | 96 / 192 / 336 / 512 / 720 | 0.8997 / 0.9131 / 0.9430 / 1.0150 / 0.9432 | 0.7155 / 0.7200 / 0.7283 / 0.7516 / 0.7303 |

### 알게 된 것

- 시드는 원인이 아니다. 같은 칸의 DLinear는 시드에 따라 0.643~1.052로 흔들렸지만, NLinear는 0.943~0.958로 안정적이다. "DLinear처럼 시드에 민감한 칸일 것"이라는 이전 판의 가설은 틀렸다.
- 어떤 설정에서도 MSE가 1.03 근처일 때 MAE는 0.75~0.77이다. 논문의 MAE 0.780은 이 관계에서 벗어난다. 학습률·배치·입력 길이만 다른 설정으로는 나오지 않는 값으로 보인다.

### 남은 가설 (모두 미확인)

- 다른 코드 버전으로 만든 값이다. NLinear는 2022-08-15에 처음 공개됐고, 논문 최종본도 같은 시기다. 공개 전 내부 버전의 NLinear가 달랐을 수 있지만 확인할 방법이 없다.
- 표에 옮길 때 다른 칸(예: NLinear-I, 다른 데이터셋)의 값이 들어갔다. 단변량 ETTh1 720의 오타(6절)와 같은 종류다. 다만 공식 LTSF-Benchmark.md의 NLinear-I 환율 값과는 아직 대조하지 않았다.

### 추가 확인

- 공식 LTSF-Benchmark.md의 개별 모델 버전 환율 720 값: NLinear-I 1.133 / 0.785, DLinear-I 1.499 / 0.940, Linear-I 1.658 / 1.033. 어느 것도 1.033 / 0.780과 같지 않다.
- 2022-08 코드에서 NLinear에 `--individual`을 붙여도 결과가 0.9430 / 0.7283으로 똑같다. 이 시점의 NLinear는 이 옵션을 받지 않는다(개별 버전은 2022-12-07 `b9ca453`에서 추가됨).

### 결론

학습률, 배치, 시드, 입력 길이, 개별 버전 어느 쪽으로도 이 값이 나오지 않는다. 공개된 코드와 스크립트로는 재현할 수 없는 칸으로 닫는다. NLinear 20칸 중 이 칸만 남는다.

### 남은 방법

단변량 ETTh2 96(2번)과 함께 저자에게 GitHub issue로 묻는다. 물을 내용: "Table 2의 NLinear 환율 720(1.033 / 0.780)을 만든 코드 버전과 설정."

## 5. NLinear ETTm2 336 (ETTh2 720은 해결)

2022-08 코드와 모델별 학습률(`confirmed_causes.md` 8절)을 적용한 뒤에도 남은 작은 차이다. ETTh2 720은 0.3960 / 0.4361(논문 0.394 / 0.436), ETTm2 336은 0.2748 / 0.3271(논문 0.274 / 0.327)이다. 두 칸 모두 MAE는 셋째 자리까지 맞고 MSE만 0.002, 0.0008 다르다. 학습률 7개(0.1~0.0001) × 배치 3개(8, 16, 32)로 훑었다(`nlinear_nearmiss_sweep_aug2022.csv`). ETTh2 720은 학습률 0.005, 배치 32에서 0.3941 / 0.4355로 일치해서 해결했다(`confirmed_causes.md` 8절). ETTm2 336은 배치 8에서 학습률 0.005와 0.01 두 곳이 일치하고, 스크립트의 배치 32에서는 어떤 학습률도 맞지 않는다. 값이 0.274~0.276에 몰려 있어서 21번 중 2번 맞은 것이 우연일 가능성도 있다. 단변량 ETTh2 96처럼 설정을 하나로 정할 수 없는 칸으로 남긴다.

## 덧붙임: 마지막으로 해 본 확인 (2026-11-13)

- **NLinear 환율 720, 1/L 초기화:** 2022-08 NLinear 코드에는 `# self.Linear.weight = nn.Parameter((1/self.seq_len)*torch.ones(...))` 줄이 주석으로 남아 있다. 논문 당시에는 DLinear처럼 이 초기화를 켜고 돌렸을 수 있어서 켜고 시드 5개로 돌렸다. 0.9415~0.9563으로, 끈 경우(0.9430~0.9580)와 거의 같고 논문 1.033과는 멀다. 원인이 아니다(`nlinear_exchange720_init_check.csv`).
- **NLinear 환율 720, 이후 코드 버전:** 2022-08 이후 NLinear 모델 파일은 2022-12(`b9ca453`, `--individual` 추가)에만 바뀌었고 개별 모드가 아닌 경로는 같다. 환율 스크립트는 2022-08 이후 바뀌지 않았다. 남은 차이는 2023-03의 채점 변경뿐인데, 다른 칸에서 영향이 0.005 이하였으므로 0.09를 설명할 수 없다.
- **다변량 ETTm2 96, 채점 방식:** 2022-06 코드에서 테스트 마지막 배치까지 채점해도 0.16765 / 0.25980으로 거의 같다(논문 0.167 / 0.260). 이 칸은 7번째 epoch에 조기 종료하므로 학습 길이도 원인이 아니다.

이로써 실험으로 해 볼 수 있는 것은 거의 다 해 봤다. 남은 네 칸 중 둘(단변량 ETTh2 96, NLinear ETTm2 336)은 논문값이 나오는 설정이 둘이라 실험으로는 가릴 수 없고, 나머지 둘(NLinear 환율 720, 다변량 ETTm2 96)은 저자의 실제 실행 기록 없이는 더 좁히기 어렵다.

- **NLinear 환율 720, 오타 가능성:** LTSF-Benchmark.md 둘째 표의 NLinear 행(파일에는 행 이름이 DLinear로 바뀌어 있다)에도 환율 720이 1.033 / 0.780으로 같은 쌍이다. 두 곳에서 같은 값을 보고했으므로 표를 옮기다 생긴 오타로 보기는 어렵다. 학습률을 올리면 MSE는 논문 쪽으로 가지만(0.01: 1.014, 0.05: 1.041) MAE는 0.758~0.763에 머물러 0.780에 닿지 않는다.
